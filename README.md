# Mero Swasthya

A modern appointment booking frontend for hospitals, clinics, and doctors across Nepal.

## Overview

Mero Swasthya is a React + Vite application that helps patients discover healthcare providers, browse services, and explore provider dashboards. It uses mocked in-memory data for hospitals, clinics, doctors, and appointment flows, making it a good starting point for a real booking platform.

## Features

- Browse hospitals, clinics, and doctors
- View detailed provider pages
- Explore services and featured listings
- Patient dashboard and appointment pages
- Provider dashboard, appointments, and schedule pages
- Responsive UI built with Tailwind CSS and shadcn/ui components

## Tech Stack

- React 18
- TypeScript
- Vite
- React Router
- TanStack Query
- Tailwind CSS
- shadcn/ui and Radix UI

## Getting Started

### Prerequisites

- Node.js 18 or newer
- bun or npm

### Install

```bash
bun install
```

If you prefer npm:

```bash
npm install
```

### Run Locally

```bash
bun run dev
```

Or:

```bash
npm run dev
```

## Scripts

- `dev` - start the development server
- `build` - create a production build
- `build:dev` - build using the development mode
- `preview` - preview the production build locally
- `lint` - run ESLint
- `test` - run Vitest once
- `test:watch` - run Vitest in watch mode

## App Routes

- `/` - home page
- `/login` - login page
- `/register` - registration page
- `/services` - services listing
- `/hospitals` - hospitals listing
- `/hospitals/:id` - hospital details
- `/clinics` - clinics listing
- `/clinics/:id` - clinic details
- `/doctors` - doctors listing
- `/doctors/:id` - doctor details
- `/dashboard` - patient dashboard
- `/dashboard/appointments` - patient appointments
- `/dashboard/profile` - patient profile
- `/provider` - provider dashboard
- `/provider/appointments` - provider appointments
- `/provider/schedule` - provider schedule
- `/provider/profile` - provider profile

## Notes

- The current app uses local mock data and does not connect to a backend API yet.
- Images and listing data are seeded from static sample content in the repository.
- Firebase support is bootstrapped in [src/lib/firebase.ts](src/lib/firebase.ts), but it stays disabled until the required `VITE_FIREBASE_*` environment variables are provided.

## Feature Walkthrough

1. Start on the home page to browse featured hospitals, clinics, doctors, and service highlights.
2. Use the listing pages to filter and explore healthcare providers by category.
3. Open a provider details page to review the description, availability, and contact information.
4. Visit the patient dashboard to view appointment-related pages and profile details.
5. Visit the provider dashboard to manage appointments and schedules.

## Backend / API Plan

The app currently relies on mock data in `src/data/mockData.ts`. A future backend can replace this layer with real services for authentication, provider listings, availability, and appointment booking.

## Firebase Setup

Firebase is now wired in as the first backend option for the app.

### Environment Variables

Copy [.env.example](.env.example) to `.env` and fill in your Firebase project values.

### Available Exports

- `firebaseApp` - initialized Firebase app or `null` when config is missing
- `firebaseAuth` - Firebase Auth instance or `null`
- `firestore` - Firestore instance or `null`
- `hasFirebaseConfig()` - helper that reports whether Firebase is configured

### Next Integration Steps

- Move authentication to Firebase Auth
- Replace appointment localStorage storage with Firestore
- Store provider and patient profiles in Firestore
- Add security rules before using the app in production

### Suggested API Areas
